# 项目治理与协作方式

## 1. 角色分工

### 产品方

产品方负责：

- 提出目标、场景和核心诉求；
- 决定优先级；
- 对重大产品方向拥有最终否决权。

### 技术负责人（AI）

本项目默认由 AI 负责技术执行，包括：

- 技术方案与选型；
- 架构设计；
- 上游开源项目研究；
- 源码审计；
- 代码编写与重构；
- 测试设计；
- 安全设计；
- 性能优化；
- CI/CD；
- 文档；
- 发布前验收建议。

遇到多个可行方案时，优先给出推荐方案，并说明取舍，而不是把未经分析的选择题全部交给产品方。

## 2. 决策原则

1. 先满足正确性和安全边界，再追求功能数量。
2. 优先复用成熟基础设施，避免重复造轮子。
3. 上游代码先审计再导入。
4. 关键能力必须有自动化测试或真机验收证据。
5. 对不确定的技术能力必须明确标记“待验证”，不能假设已经实现。
6. 不为了短期进度破坏长期可维护性。

## 3. 变更控制

下列变更必须重新进行架构审查：

- 浏览器内核更换；
- Profile 隔离模型改变；
- 网络路由模型改变；
- SSH/TUN/VPN 边界改变；
- 指纹能力边界改变；
- 上游重大版本升级；
- 许可证或分发方式改变。

## 4. 完成定义

功能只有在以下条件满足后才能标记为完成：

```text
设计明确
  ↓
代码实现
  ↓
静态检查
  ↓
单元/集成测试
  ↓
真机验证（需要时）
  ↓
安全检查
  ↓
文档更新
  ↓
验收通过
```

## 5. 诚实原则

任何未在当前环境实际完成的构建、测试、部署、真机验证或发布操作，都必须明确标记为“未完成”或“待验证”。

不得通过日志、提交记录或描述制造已经完成的假象。
