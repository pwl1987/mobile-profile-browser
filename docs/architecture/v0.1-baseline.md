# V0.1 架构基线

**状态：冻结候选基线。**

## 1. 产品边界

本项目是运行在真实 Android 设备上的多 Profile 浏览器。V0.1 的任务是建立可靠的 Profile、浏览器数据、网络抽象和安全基础；不宣称已经完成完整的反指纹或匿名能力。

### V0.1 范围

- Profile 创建、读取、修改、删除与稳定标识；
- 每个 Profile 独立的浏览器会话与持久化状态；
- Profile 激活、切换与崩溃恢复；
- MobileProfile 与 BrowserProfile 的引用关系；
- DeviceProfile 基础模型；
- NetworkRoute、Provider、FailurePolicy、NetworkHealth 基础模型；
- 安全存储与日志边界；
- 基础单元测试。

### V0.1 明确不做

- 完整指纹伪装引擎；
- 多跳 Route Graph 的实际运行；
- 完整 Android VpnService/TUN 产品化；
- 云端同步；
- 远程控制；
- 针对特定平台的账号注册或规避逻辑。

## 2. Profile 边界

每个 Profile 应该拥有明确的数据所有权：

```text
PROFILE
├── Cookie
├── LocalStorage / IndexedDB
├── 浏览会话
├── 权限
├── Cache（按引擎隔离能力验证）
├── History（若配置为 Profile 级）
└── Service Worker / 站点状态
```

全局应用配置不得隐式替代 Profile 状态。

## 3. 浏览器运行时

V0.1 使用 WebLibre 作为初始浏览器底座。WebLibre 的 Gecko/GeckoView、Profile 文件系统、存储、Secure Storage 和现有代理基础设施优先复用。

本项目自己的 `MobileProfile` 不直接等于 WebLibre 的 Profile，而通过稳定引用关联。

第一次代码导入必须固定准确的上游 commit，并保证构建可复现。

## 4. 网络架构

```text
MobileProfile
      ↓
NetworkRoute
      ↓
RouteResolver
      ↓
ProviderRegistry
      ↓
ProviderRuntime
      ↓
实际网络出口
```

Provider 预留：

```text
DIRECT
HTTP
SOCKS5
SING_BOX
SSH
WIREGUARD
VPN_TUN
TOR
```

SSH 只是 Provider 之一。

## 5. 网络安全边界

每个非直连线路至少应有：

- Provider 配置引用；
- 必要的凭据引用；
- 信任信息引用；
- DNS 策略；
- IPv4/IPv6 策略；
- WebRTC 策略；
- FailurePolicy；
- 健康状态。

要求身份保护的线路默认 Fail Closed。禁止代理失效后无提示地自动回落到 DIRECT。

## 6. DeviceProfile

DeviceProfile 描述相互一致的真实设备能力，而不是随机字段。

Find N3 必须支持：

- 外屏；
- 内屏；
- 折叠；
- 展开；
- 转换中；
- 实际 Window Metrics；
- 实际 DPR；
- 实际触控能力。

厂商规格只能作为硬件基线，网站可见值必须以真机观测结果为准。

## 7. 身份保护

核心安全目标之一是减少真实设备、真实网络和真实浏览状态的无意暴露。

必须单独验证：

- 浏览状态身份；
- 设备表现身份；
- 网络身份；
- 应用/系统身份。

项目不承诺绝对匿名，也不把修改 User-Agent 等同于完成指纹保护。

## 8. 数据安全

- SSH 私钥、密码、令牌不得写入普通 Profile JSON；
- 使用 Android Keystore 等受保护存储；
- 日志默认脱敏；
- 导出默认加密；
- 删除 Profile 后验证作用域数据清理；
- 不记录完整 Cookie、认证 Header、私钥或敏感 URL。

## 9. V0.1 验收门槛

全部通过后才能进入 V0.1 Release：

1. 真机能够安装、启动并浏览；
2. 至少两个 Profile 可以创建、切换、停止、恢复和删除；
3. Cookie / Storage / 权限不会跨 Profile 串联；
4. RuntimeInstance 能正确区分崩溃前后的运行实例；
5. Provider 和 NetworkRoute 校验能够拒绝明显非法配置；
6. 真实网络出口和 DNS 状态可以测试；
7. 保护线路故障不会静默直连；
8. 上游基线可重复构建；
9. 领域单元测试通过；
10. 第三方许可证与版权义务完成审计。
