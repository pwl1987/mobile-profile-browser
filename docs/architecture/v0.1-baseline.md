# V0.1 架构基线

**状态：待实施评审的 V0.1 基线。**

## 1. 产品边界

本项目是一个运行在 Android 真机上的多 Profile 浏览器。V0.1 负责建立正确的 Profile、存储、网络和安全边界；**不宣称已经完成完整的反指纹能力**。

### V0.1 范围

- Profile 创建、读取、修改、删除与稳定标识。
- 每个 Profile 独立的浏览器会话与状态。
- Profile 激活与切换。
- 持久化 Profile 元数据。
- 网络配置抽象。
- DeviceProfile 数据模型。
- 安全边界与测试契约。

### V0.1 明确不做

- 完整指纹伪装引擎。
- SSH 协议实现。
- 仅 Root 可用的流量拦截方案。
- 云端同步。
- 远程控制。
- 自动注册账号或针对特定平台的规避逻辑。

## 2. Profile 边界

每个 Profile 拥有：

- 浏览器/会话数据；
- Cookie；
- LocalStorage / IndexedDB 及同类站点存储；
- 在浏览器引擎隔离能力允许范围内的 Cache；
- 权限状态；
- 明确声明为 Profile 级的书签、历史和设置；
- DeviceProfile 引用；
- NetworkRoute 引用。

全局应用配置不得隐式替代 Profile 状态。

## 3. 浏览器运行时

V0.1 使用 WebLibre 作为初始浏览器底座。WebLibre 当前是基于 Dart/Flutter、Gecko/GeckoView 的 Android 浏览器工程，并已有 Profile、隔离和代理相关能力。

成熟的浏览器基础设施优先复用；只有明确无法满足本项目边界时才进行修改。

第一次代码导入必须记录准确的上游 commit/tag，并保证能够复现构建。

## 4. 网络层

```text
Profile
  ↓
RouteSelector
  ↓
ProxyEndpoint
  ↓
（可选）SSH 隧道
  ↓
（可选）TUN/VPN 路由
  ↓
Internet
```

Profile 只引用逻辑 NetworkRoute，不硬编码本地端口。隧道生命周期由 NetworkService 管理。

## 5. DeviceProfile

DeviceProfile 是描述一组**相互一致的设备/浏览器能力**的声明式配置，而不是随机字段集合。

后续至少需要建模：

- 设备系列/型号；
- Android 版本；
- 浏览器/引擎版本兼容性；
- 屏幕与 viewport 特征；
- DPR；
- 触控能力；
- 语言/地区；
- 时区；
- 硬件并发能力等级；
- Client Hints 策略；
- WebGL 能力等级。

底层引擎无法可靠控制的字段必须标记为 **observed（观测）**、**derived（推导）** 或 **unsupported（不支持）**，不能虚假标记为已伪装。

## 6. 数据安全

SSH 私钥等敏感数据不得写入普通 Profile JSON，也不得进入日志。凭据必须使用 Android Keystore 等受保护存储。导出功能默认必须加密。

## 7. V0.1 验收门槛

V0.1 在以下项目全部通过前不得发布：

1. 至少可以创建并切换两个 Profile；
2. Profile A 的登录/会话状态无法在 Profile B 观察到；
3. 删除 Profile 后，其作用域数据按照保留策略得到正确清理；
4. Profile 切换过程中发生崩溃不会破坏活动 Profile 注册表；
5. DeviceProfile 校验器能够拒绝不兼容组合；
6. 密钥等秘密不会出现在日志、崩溃报告或普通备份中；
7. 上游基线可以重复构建；
8. 真实 Android 设备能够安装、启动并完成基本浏览；
9. NetworkRoute 的健康状态可验证；
10. 配置了 Fail Closed 的代理线路断开后不会静默回落到直连。
