# V0.1 架构基线

**状态：已进入实现前评审；本文档作为 V0.1 的冻结边界。**

## 1. 产品边界

本项目是一款 Android 浏览器，用于在一台设备上管理多个相互隔离的浏览 Profile。V0.1 只建立可靠的 Profile 与浏览器基础架构，**不宣称已经实现完整的反检测能力**。

### V0.1 纳入范围

- Profile 创建、修改、删除和稳定标识；
- 每 Profile 独立的浏览会话与状态；
- Profile 激活与切换；
- Profile 元数据持久化；
- 网络配置抽象；
- 设备配置数据模型；
- 安全边界和测试契约；
- WebLibre 上游代码级审计及可复现基线记录。

### V0.1 不纳入

- 完整指纹伪装引擎；
- SSH 实际实现；
- 仅 Root 可用的流量拦截；
- 云同步；
- 远程控制；
- 自动注册账号或针对特定平台的规避逻辑。

## 2. Profile 边界

每个 Profile 原则上拥有：

- 浏览器 / 会话数据；
- Cookie；
- LocalStorage / IndexedDB 及等效网站存储；
- 在引擎隔离能力允许范围内的缓存；
- 网站权限；
- 明确标记为 Profile 级的书签、历史记录和设置；
- Device Profile 引用；
- Network Route 引用。

全局应用配置不得成为 Profile 状态的隐式替代品。

## 3. 浏览器基础

初始基础采用 WebLibre。当前上游是 Dart/Flutter 工作区，底层使用 Gecko/GeckoView，并已经包含 Profile、隔离浏览和代理相关能力。我们必须先完成代码级审计，再决定每项能力是直接复用、适配、替换还是重新实现。

首次导入代码必须记录：

- 上游仓库；
- 上游 commit / tag；
- 导入时间；
- 本地修改范围；
- 许可证边界；
- 构建工具链版本。

## 4. 网络分层

```text
Profile
  ↓
RouteSelector
  ↓
ProxyEndpoint
  ↓
（可选）SSH Tunnel
  ↓
（可选）TUN/VPN Routing
  ↓
Internet
```

Profile 只引用逻辑路由，不能硬编码本地端口。隧道的创建、保活、重连和销毁属于 `NetworkService`。

## 5. 设备配置

Device Profile 是描述一致设备 / 浏览器环境的声明式配置，并必须包含兼容性和能力验证信息。

后续至少需要建模：

- 设备系列 / 型号；
- Android 版本；
- 浏览器 / 引擎版本兼容性；
- 屏幕 / Viewport 特征；
- DPR；
- 触控能力；
- Locale / Language；
- Timezone；
- Hardware Concurrency 等级；
- Client Hints 策略；
- WebGL 能力等级。

底层引擎无法可靠控制的字段必须明确标记为 **受控 / 派生 / 观测 / 不支持**，不得把普通配置项错误描述成“已伪装”。

## 6. 数据安全

SSH 私钥、代理密码等敏感值不得直接写入普通 Profile JSON，也不得进入日志。敏感凭据必须使用 Android Keystore 保护。未来导出功能默认使用加密格式。

## 7. V0.1 验收门槛

V0.1 只有同时满足以下条件才能标记完成：

1. 至少创建并切换两个 Profile；
2. Profile A 的登录状态无法在 Profile B 观察到；
3. 删除 Profile 后，其约定范围内的数据被清理；
4. Profile 切换过程中发生崩溃，不会破坏活动 Profile 注册表；
5. Device Profile 能拒绝不兼容参数组合；
6. Secret 不出现在普通日志、崩溃报告或未加密备份中；
7. 上游基线可以在干净环境中复现构建；
8. 已形成 WebLibre 代码级审计报告，并明确首批导入范围。
