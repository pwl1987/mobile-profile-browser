# 身份与隐私架构

## 目标

本项目的核心安全目标之一，是**默认减少真实设备、真实网络与真实浏览状态向网站暴露的信息**。

这不是“绝对匿名”承诺。应用无法控制所有系统、浏览器引擎、运营商、网络、网站和第三方服务行为，因此所有能力必须标记实际控制范围。

## 身份分层

一个 Profile 的网络与浏览身份至少拆成四层：

```text
Profile 身份
├── 浏览器状态身份
│   ├── Cookie
│   ├── LocalStorage
│   ├── IndexedDB
│   ├── Cache
│   └── 权限
│
├── 设备表现身份
│   ├── 屏幕
│   ├── DPR
│   ├── 触控
│   ├── Locale
│   ├── Timezone
│   ├── Client Hints
│   └── 图形能力
│
├── 网络身份
│   ├── 出口 IP
│   ├── DNS
│   ├── IPv4 / IPv6
│   ├── WebRTC 网络特征
│   └── Provider 特征
│
└── 应用/系统身份
    ├── Android 系统信息
    ├── 应用版本
    ├── 系统网络能力
    └── 设备原生可观测信息
```

## 核心原则

### 1. 最小暴露

不为了所谓“指纹伪装”去主动增加网站可识别字段。能够关闭、隔离或稳定化的暴露面优先处理。

### 2. 一致性

不同暴露字段必须相互一致。宁可报告“不支持控制”，也不能生成互相矛盾的设备特征。

### 3. 身份断开

新 Profile 默认不继承旧 Profile 的 Cookie、站点存储、权限、历史和登录会话。

复制 Profile 必须要求用户明确选择哪些内容可以复制；默认不复制身份数据。

### 4. 网络身份与浏览身份解耦

更换 NetworkRoute 不自动迁移 Cookie；更换 DeviceProfile 不自动改变历史会话数据。

## 必须重点防止的真实身份暴露

- 真实公网 IPv4 / IPv6 泄漏；
- 系统 DNS 泄漏；
- WebRTC 地址泄漏；
- 跨 Profile Cookie / Storage 串联；
- 未经用户授权的跨 Profile 权限共享；
- 旧 Profile 的缓存、历史和 Service Worker 残留；
- 通过应用日志泄漏 URL、Cookie、令牌或凭据；
- 代理断线后的隐式直连；
- 过度依赖随机指纹导致稳定、异常或互相矛盾的特征。

## Find N3 特别要求

Find N3 是折叠设备，因此必须把真实设备的外屏、内屏和姿态变化作为一个连续运行时状态处理。

```text
设备状态
├── 折叠
├── 展开
└── 转换中
```

屏幕尺寸、viewport、DPR 和触控行为以真机运行时观测为准，不直接把厂商规格表当成网站实际可见值。

## 安全边界

```text
           MobileProfile
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    Browser   Device    Network
     State    Profile     Route
       │         │         │
       └─────────┼─────────┘
                 ↓
         Identity Policy
                 ↓
      允许暴露 / 隔离 / 阻断
```

## 不能承诺的事项

本项目不承诺：

- 对所有网站完全不可识别；
- 对抗所有商业风控系统；
- 隐藏 Android 设备所有原生属性；
- 在不修改 Gecko/系统底层的情况下任意伪造所有浏览器指纹属性；
- 提供法律意义上的匿名性。

项目追求的是**可控、可验证、最小化暴露的移动 Profile 隔离环境**。
