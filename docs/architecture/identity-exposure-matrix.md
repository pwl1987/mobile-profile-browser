# 身份暴露矩阵

## 目的

把“不要暴露真实身份”从口号变成可测试的工程要求。

| 暴露面 | 目标 | V0.1 | 后续 |
|---|---|---|---|
| Cookie / Storage | Profile 独立 | 必须隔离 | 持续测试 |
| 权限 | Profile 独立 | 必须隔离 | 持续测试 |
| 历史 / Cache / Service Worker | Profile 独立 | 必须隔离 | 持续测试 |
| 公网 IPv4 | 使用所选线路 | 验证 | 持续监测 |
| 公网 IPv6 | 不得绕过线路 | 验证 | 持续监测 |
| DNS | 遵守线路策略 | 验证 | 持续监测 |
| WebRTC | 不泄漏不应暴露的网络地址 | 验证 | 深化 |
| User-Agent | 与 DeviceProfile 一致 | 观察 | 后续控制 |
| Client Hints | 与设备模型一致 | 观察 | 后续控制 |
| Screen / DPR | 与真实运行态一致 | 观察 | 后续控制 |
| Touch | 与设备状态一致 | 观察 | 后续控制 |
| WebGL / Canvas / Audio / Fonts | 最小暴露 + 一致性 | 观察 | 深化 |
| Android 原生信息 | 不虚假承诺完全隐藏 | 明确边界 | 后续研究 |

## 核心结论

本项目的“身份保护”分为：

1. **状态隔离**：阻断跨 Profile 的持久化身份关联。
2. **网络隔离**：阻断真实网络出口泄漏。
3. **设备一致性**：使可控制字段与实际设备模型一致。
4. **暴露最小化**：不主动增加不必要的唯一特征。
5. **能力诚实**：无法控制的字段必须标明 observed/derived/unsupported。

任何功能只有在对应暴露面有验证手段后才可标记为完成。
